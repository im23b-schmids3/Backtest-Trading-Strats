# Phase E plan

Phase E may add a native futures data adapter, exchange-session and rollover
handling, fill/fee/slippage models, multi-account statistical scenario batches,
and operational deployment controls. It must preserve the frozen Phase C
candidate and the Phase D hashes and ledgers.

Before Phase E, the project needs current provider-rule re-verification, native
contract data-quality evidence, independent compliance review, and a decision
about whether external-account operations are in scope. Phase D synthetic and
proxy fixtures are not sufficient authorization for paper or live trading.
